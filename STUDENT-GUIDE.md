# Student Guide

## Weekly routine

Attend and code Monday-Friday. Before each session, pull the latest changes and create a small branch or working directory. Commit purposeful checkpoints during practical work. On Friday, submit the assignment, a short reflection, and a link to your repository or pull request.

Saturday is optional: catch up, attend mentorship, improve a project, or participate in peer review. Sunday is for rest and planning.

## Work offline first

Keep a local clone, save lesson files and package wheels where possible, and run programs and tests before seeking internet access. Commit locally after each meaningful change; push when connected. Keep project backups on a second local device or trusted drive. Never store passwords, API tokens, or student-sensitive data in Git.

Every major submission needs a README with setup, run, and test steps; meaningful commits; clear names; and evidence that the program runs. Use [the submission guide](docs/submission-guidelines.md) and [templates](templates/).

Ask peers or instructors to explain concepts, but write and explain your own solution. When stuck, record the error, command, expected result, and attempts.
