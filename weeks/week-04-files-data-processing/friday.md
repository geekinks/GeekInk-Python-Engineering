## Detailed lesson content

A virtual environment prevents one project's packages affecting another. For standard-library work it can be empty, but it is still good practice. Record dependencies only when used.

Before coding, describe the input, processing, and output in ordinary language. Run the smallest possible version, then extend it one change at a time. Read the error message before asking for help.

## Code example

~~~python
python3 -m venv .venv
# activate it, then run python -m pip list
~~~
